# Сервис работы с полигонами и проверка попадания точки

Сервис для хранения многоугольников, выполнения над ними геометрических операций
и быстрого ответа на запрос **«попадает ли точка в полигон?»**.

Бэкенд — Spring Boot + JTS (Java Topology Suite), фронтенд — простой web-UI на Canvas
для рисования полигонов, редактирования вершин и визуальной проверки точек.

---

## Какую задачу решает продукт

1. **Хранение полигонов** — создание, редактирование (перемещение/добавление/удаление вершин) и удаление многоугольников. Поддерживаются полигоны **с отверстиями** и мультиполигоны.
2. **Импорт/экспорт геоданных** — приём геометрии в форматах **GeoJSON** и **WKT**, выдача полигона обратно в WKT.
3. **Геометрические операции** — объединение, пересечение, разность, симметрическая разность и буферизация (через JTS).
4. **Проверка попадания точки** — корректный ответ «внутри / снаружи» с обработкой граничных случаев (точка на границе, точка в отверстии). Для ускорения используется пространственный индекс (grid).
5. **Валидация геометрии** — проверка корректности полигонов перед сохранением.

## Технологии

| Слой | Технология |
|------|-----------|
| Язык | Java 17 |
| Фреймворк | Spring Boot 3.2 (Web, Data JPA, Validation) |
| Геометрия | JTS (Java Topology Suite) 1.19 |
| База данных | MySQL 8 |
| Документация API | springdoc-openapi (Swagger UI) |
| Сборка | Gradle (wrapper в комплекте) |
| Фронтенд | HTML + Canvas + чистый JS |

### Ключевые алгоритмы
- **Point-in-polygon** — алгоритм winding number с явной обработкой границ и отверстий (`geometry/PointInPolygon.java`). Перед основной проверкой отсекаются точки вне bounding box.
- **Пространственный индекс** — равномерная сетка (grid index) для быстрого отбора кандидатов (`indexing/GridIndex.java`).

## Как запустить

### Вариант 1. Docker Compose (рекомендуется)

Поднимает MySQL и приложение одной командой. Локально нужен только Docker.

```bash
docker compose up --build
```

После старта:
- Веб-интерфейс: <http://localhost:8082/>
- Swagger UI: <http://localhost:8082/swagger-ui.html>

> Приложение внутри контейнера слушает порт `8080`, наружу проброшен `8082`.

### Вариант 2. Быстрый локальный запуск без MySQL (профиль `local`, БД H2)

Если не хочется поднимать MySQL — есть профиль `local` со встроенной базой H2
(данные хранятся в памяти, пока работает приложение). Нужен только JDK 17.

```bash
./gradlew bootRun --args='--spring.profiles.active=local'
```

Откройте <http://localhost:8080/>. Консоль БД: <http://localhost:8080/h2-console>
(JDBC URL `jdbc:h2:mem:polygons`, пользователь `sa`, без пароля).

### Вариант 3. Локальный запуск с MySQL (нужны JDK 17 и MySQL)

1. Поднимите MySQL и создайте базу:
   ```sql
   CREATE DATABASE mydb;
   ```
2. Задайте доступы к БД. Пароль **не хранится в коде** — он берётся из переменных
   окружения. Скопируйте `.env.example` в `.env` и впишите свои значения:
   ```bash
   cp .env.example .env
   ```
   Переменные: `DB_URL`, `DB_USERNAME`, `DB_PASSWORD`. Если их не задать,
   используются значения по умолчанию (`root` без пароля, база `mydb` на `localhost:3306`).
3. Запустите:
   ```bash
   ./gradlew bootRun
   ```
4. Откройте <http://localhost:8082/>.

Схема таблицы создаётся автоматически (`spring.jpa.hibernate.ddl-auto=update`).

## Как пользоваться (для проверяющих)

1. Откройте веб-интерфейс в браузере.
2. Нарисуйте полигон мышью на холсте либо вставьте геометрию в формате **WKT** / **GeoJSON**.
3. Полигоны с отверстиями отображаются с **прозрачными дырами** (границы отверстий — пунктиром).
4. Поставьте точку — сервис покажет, попадает ли она внутрь полигона (с учётом отверстий).
5. Выберите два полигона и примените операцию (объединение / пересечение / разность / буфер).

## REST API

Базовый префикс: `/polygons`

| Метод | Путь | Назначение |
|-------|------|-----------|
| `GET` | `/polygons/` | Список всех полигонов |
| `POST` | `/polygons/` | Создать полигон(ы) из **GeoJSON** |
| `POST` | `/polygons/wkt` | Создать полигон(ы) из **WKT** (`{"wkt": "..."}`) |
| `GET` | `/polygons/{id}/wkt` | Получить полигон в формате WKT |
| `POST` | `/polygons/check?id={id}&x={x}&y={y}` | Проверить попадание точки в полигон (через индекс) |
| `POST` | `/polygons/check-multiple` | Проверить точку по списку полигонов |
| `POST` | `/polygons/operation` | Геометрическая операция (см. ниже) |
| `PUT` | `/polygons/{id}/vertex/move` | Переместить вершину |
| `POST` | `/polygons/{id}/vertex/add` | Добавить вершину |
| `DELETE` | `/polygons/{id}/vertex/{ringIndex}/{vertexIndex}` | Удалить вершину |
| `DELETE` | `/polygons/{id}` | Удалить полигон |

### Пример: создать полигон с отверстием (GeoJSON)
```bash
curl -X POST http://localhost:8082/polygons/ \
  -H "Content-Type: application/json" \
  -d '{
        "type": "Polygon",
        "coordinates": [
          [[0,0],[100,0],[100,100],[0,100],[0,0]],
          [[30,30],[70,30],[70,70],[30,70],[30,30]]
        ]
      }'
```

### Пример: проверить точку
```bash
curl -X POST "http://localhost:8082/polygons/check?id=1&x=50&y=50"
# -> {"polygonId":1,"inside":false}   // точка в отверстии
```

### Пример: операция над двумя полигонами
```bash
curl -X POST http://localhost:8082/polygons/operation \
  -H "Content-Type: application/json" \
  -d '{"operation":"intersection","polygonIdA":1,"polygonIdB":2}'
```
Допустимые `operation`: `intersection`, `union`, `difference`, `symDifference`, `buffer`
(для `buffer` вместо `polygonIdB` передаётся `distance` и опционально `segments`).

## Политика граничных случаев

- Точка **строго внутри** → `inside = true`.
- Точка **в отверстии** → `inside = false`.
- Точка **на границе** (внешней или на границе отверстия) → считается принадлежащей полигону (`inside = true`). Реализовано явной проверкой принадлежности отрезку с допуском `EPSILON = 1e-9`.
